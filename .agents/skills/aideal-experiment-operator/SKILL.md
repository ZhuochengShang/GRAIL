# AIDEAL experiment operator

Locate the user's AIDEAL root; confirm `experiments/external/automation` exists.
Do not assume a home directory, interpreter, or that the current working
directory is the project. Read its `AIDEAL_DESIGN_LOGIC.md` for the current
execution boundaries and `experiments/external/automation/README.md` for tools.

## Resume

Inspect watchdog plans/states/logs, heartbeats, locks, actual processes and
worktree branches first. A stale `running` state is not a living process.
Preserve active jobs. Reuse completed evidence only under compatible source,
manifest, configuration, fixtures and treatment fingerprints. Verify exclusive
mutable output ownership. In current plans, `max_restarts: 0` means unlimited
retries; final comprehension code-fix rounds remain zero.

Honor the user's current priorities; dated plans can contain superseded serial
queues. Distinguish idle admission waiters from workers doing measured work.
Routine work already authorized by the user needs no repeated approval.

## Diagnose

Use the passive automation report and native ledgers. Separate provider error,
dependency/import identity, fixture/output path, input contract, and assertion
issues. Candidate classification is not proof that documentation caused a
failure. Keep native scores and hash-bound reviews separately. Run diagnostics
only in isolated outputs; never overwrite measured snippets or insert successes
into a final result. Do not expose source-informed review to the audience model.

Resolve `files.project_profile` from effective YAML; tslearn full235 does not
use the historical base profile. Record direct listed config layers according
to the actual loader, not assumed recursive inheritance. A package inventory
does not certify every worker's imports or every optional dependency.

## Report

Use recorded results, attempt/repair ledgers, data formats and actual sample
construction, plus explicit missing artifacts. Keep provider retries, code
fixes, document rounds and diagnostic changes distinct. Report scoped timing
scenarios with unknown stages; never convert a deadline into a completion claim.
Include the data/methods appendix and architecture note in the final package.

Current observers own distinct namespaces. Check an observer's lock before
starting another; modifying its source does not hot-reload a running process.
The passive extension owns only `data_validation/automation/`. Consult its
README for the module command and tests. Staged input contracts, quota admission
and new prompts are not active merely because their files exist. Changes to
the measured protocol require a new version and matched comparison design.
